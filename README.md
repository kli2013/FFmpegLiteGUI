### 简介 一个集 HandBrake 转码、mkvtoolnix 封装与非线性编辑于一体的轻量 FFmpeg GUI

**功能定位**：  
这是一个**多功能 FFmpeg 图形界面**，不仅覆盖了 HandBrake 约 90% 的转码与滤镜功能，还融合了 **mkvtoolnix 的封装能力**，并在此基础上实现了**轻量级非线性编辑**功能。

本程序只是一个外壳GUI,需要FFmpeg本体 [[FFmpeg下载地址](https://github.com/BtbN/FFmpeg-Builds/releases)],推荐xxx-win64-gpl-shared 版,这个共享版解压后的总体大小比较小, 程序用了FFmpeg三件套, 如果每个都下载独立版, 那么加起来会大2倍.    
  下载后解压到程序目录或者子目录,具体配置方法请看[[配置FFmpeg](docs/SetupFFmpeg.md)]
  
---

### 核心能力

| 模块 | 能力描述 |
|------|----------|
| **视频转码-主要** | 支持 CPU/硬件编码、多种码率控制（CRF/CQ/比特率）、预设、高级参数（tune/profile/level），以及缩放、裁剪、旋转、变速、降噪、锐化、字幕烧录等常用滤镜。亮度、对比、饱和、伽玛、色相、色饱和，能想到的基本都覆盖了。[详细说明](docs/transcode.md)  |
| **水印叠加** | 图片/视频水印，支持循环、绿幕抠像、自适应尺寸与位置，可视化位置编辑窗口可自由拖动矩形位置。叠加滤镜的研究比我实现主转码功能的时间还要久。 操作逻辑同以下画中画的子视频，可在下面查看详细说明。|
| **封装/合并-轻量** | 类似 mkvtoolnix 的流复制与封装，支持多音轨、多字幕的灵活选择（基于原始 stream index）。不过只实现了基本功能，专业的元数据修改了解不多，以后可能慢慢补足。 |
| **画中画 & 非线性编辑** | 支持多视频叠加（画中画），可独立调整每个视频的缩放、裁剪、旋转、透明度、绿幕抠像、循环播放控制，以及叠加位置的自适应调整，实现了类似轻量非线性编辑器的功能。[详细说明](docs/mergeandOverlay.md) |
| **流提取-轻量** | 可批量提取文件数据流(视频、音频、字幕)，提供保留章节、清除元数据、按流类型分文件夹存放等选项，提取命令直接发送到任务队列或预览。 [详细说明](docs/extract.md)|
| **音频处理** | 多音轨混合（amix）、音量调整、静音填充、截取。 |
| **任务管理** | 队列里任务可双击编辑，多任务并行队列，支持全局停止（发送 q 信号），并可自定义 FFmpeg 命令。 |
| **预设与工具** | 预设管理（保存/加载）、播放器预览（mpv/ffplay）。mpv能预览几乎90%的复杂滤镜，ffplay只能简单单链。|

---
界面有大量悬停提示，大部分功能都可鼠标指向附近文字或者编辑框查看提示。

使用硬件编码(那些带_nvenc amf显卡后缀)模式时,需要`FFmpeg`和显卡`api`对应,如果失败可以下载旧版 `FFmpeg` 或者更新显卡驱动重新尝试。已增加自定义`FFmpeg`目录功能

纯硬件编码解码时想用软件滤镜，需要对应参数包裹，不然会报错，功能按钮在高级选项页，自动切换各种纯硬件滤镜链，具体看说明。 [详细说明](docs/transcode.md#%E6%BB%A4%E9%95%9C%E5%8A%A0%E9%80%9F%E7%A1%AC%E4%BB%B6%E6%BB%A4%E9%95%9C%E5%88%87%E6%8D%A2)

## 项目缘起

找 AI 用 Python 写的 FFmpeg GUI。

契机是 **HandBrake** 又双叒叕换了 **.NET 10**（软件开发框架），我的老 Windows 10 LTSC 2021 装了 .NET 10，运行 HandBrake 依然报错。当时就在想，一个破 FFmpeg 的外壳，需要这么追新吗？

然后在 **52pj** 看到了另外一个 FFmpeg 的 GUI 外壳：[地址](https://www.52pojie.cn/forum.php?mod=viewthread&tid=2099752&highlight=FFmpeg)，也是用的 .NET 10，我又用不了--------------------------------------不过后来想办法体验了一下，很难用，没他宣传的那么直观简单。然后还会释放一个驱动,不知道一个 `FFmpeg` 外壳弄个驱动是要干嘛,膈应人,必须用powertool等内核软件才能删除

我一气之下就气了一下，借着这个拼接命令的灵感，找 AI 根据我以前用的一个 bat（里面是我各种 FFmpeg 命令的模板，每次都手动改 goto1234 保存在发送文件运行）写了一个简易 GUI。

第一个版本居然就实现了我大部分的想法。

**我的理念就是，既然FFmpeg本体没什么限制，那么外壳就不能人为制造限制。**

### 2026-07-17 添加串接合并模式
1. **自动去黑边**现在会自动根据截取的起始时间获取相应片段的黑边，以前一直都是开头，不是很方便。
2. **可视化裁剪**的缩略图从原始 ppm 换成了 png，减少了读写次数和临时文件体积。8K 视频测试下，显示窗口慢了 0.1 秒，相比减少的 95% 体积可以接受。
3. **转换页面**添加了分段截取然后合并的功能，典型应用场景是去掉视频内部的广告，然后把两边组合起来。暂时只有精确帧模式，需要强制转码。
4. **合并页面**添加了首尾串接模式，无损 copy 的时候使用 `concat -i xxx.txt`，需要列表里的视频参数基本一致，不然可能会导致第一个视频播放完，后面连接的视频时间乱跳。不确定素材参数就还是用转码模式吧。  
   - ~~**串接模式下的子视频一定要保留子视频的音频流**~~。  基于后续更新,可用静音填充。
   - 以前只能并行封装合并，现在可以串行连接了。  
   - 个人使用场景是给某些短视频鬼畜重复几次，因为是同一个文件，可以用无损 copy；其他视频连接需要测试，先无损 copy 连接，播放没问题就不管，有问题就换编码模式重新连接。
5. 增加了一些编码预设参数的选择（tune、profile 等）和更多的高级滤镜（降噪、锐化等）。
6. 精简了一些保存到预设的参数，然后把水印的参数独立出来单独保存，主预设里应该只保存编码质量之类的，时间、水印设置等现在都屏蔽了。
7. 合并页面的流编号问题前段时间就解决了,忘了说,现在是每种不同类型的流都单独从0开始计算序号,在也不怕1个视频里有多语言音频和多字幕的情况了,现在都可以正确映射

## 2026-08-08 长命令脚本化功能测试与阈值说明
### 功能背景
在 Windows 环境下，`cmd.exe` 的命令行长度限制为 **8191 字符**，但程序内部通过 `subprocess.Popen` 调用 `CreateProcess` API 时，实际限制为 **32767 字符**。为了规避这一限制，我引入了一个自动检测机制：当命令总长度超过阈值时，将过长的滤镜参数（`-filter_complex` / `-vf` / `-af`）写入临时脚本文件，替换为 `-*_script` 形式，从而大幅缩短命令行长度。

### 测试结果
- **240+ 视频极端压力测试**：新功能成功启动转换进程，而旧脚本直接报错 `[WinError 206] 文件名或扩展名太长`。不过由于文件数量过多，转换过程卡顿明显，未等待完成。
- **60 个视频 + 满滤镜测试**：命令长度约 **30000 字符**，日常使用中几乎不会触发脚本化机制，用户无感知。

### 阈值设定（25000）
- 触发阈值设为 **25000**，预留约 7000 字符的安全余量。
- 注意：脚本化仅缩短**滤镜参数**，若输入文件路径过多（如大量 `-i`），剩余部分仍可能超过 32767 限制。
- **建议**：输入文件避免使用过深的目录结构，以免人为增加命令总长度。

  `信息页的快速命令是临时运行，用的是cmd模式，有8191字符限制。这个页面最好不要复制其他页面的太复杂的命令过来运行，就用用预设里的简单命令就好。`

####  功能更新
为了解决上述兼容性问题，在高级选项卡的“启用硬件解码”按钮后方，新增了两个快捷按钮：
- **NVIDIA**
- **AMD**

**启用条件**：仅当编码器和解码器均设置为对应显卡 NVIDIA`(xxx_nvenc、cuda、xxx_cuvid）` 或 AMD`xxx_amf`时，按钮方可启用。
**使用提示**：具体用法与参数包裹方式，请鼠标悬停按钮查看 Tooltip 提示。

####  实测反馈
目前已在 NVIDIA 显卡环境下完成测试，工作正常。
- **性能表现**：开启硬件编解码，并将软件滤镜通过参数包裹后，常规的裁剪、缩放、变速、倒放这些不改变像素的基本上不拖慢速度。
-   不过一旦开启了降噪、锐化、区块、颜色等，叠加起来速度几何级数下降，单一带一项还能接受。
-   一旦发现滤镜过多速度太慢，可以回退为全软件编码转换，可能消耗的速度还差不多。
-   不过我个人测试的样本也不多，情况按你们本地测试为准
-   自定义用纯硬件加速滤镜那些也测试过了，互相要配合的太多了，有些激活不了，各种平台能使用的硬件滤镜不一样，不通用。还不如就用这个傻瓜模式试一试，不行就直接软编码。

在未对滤镜进行参数包裹的情况下，硬件流程目前仅支持使用 `-ss` 进行跳转组合截取这一单一功能。若强行使用软件滤镜，将一律报错。
