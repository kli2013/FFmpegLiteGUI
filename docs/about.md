# 关于本项目：主线、支线与更新节奏

## 一句话定位

这个项目只围绕一条主线：**批量转码 + 打水印工作流**。

## 主线和支线

功能列表看着杂，来历其实很单纯：我最开始挖 FFmpeg 的 overlay 不是为了打水印，而是为了「左右平铺」——后来才醒悟打水印走的是同一条路，于是顺着这条线一点点深入，位置/旋转/缩放可视化编辑、动态轨迹、遮罩、绿幕抠像、画布、画中画、起始/结尾双端编辑……都是这么长出来的。

| 模块 | 属性 | 说明 |
|------|------|------|
| 批量转码 | 主线 | HandBrake 约 90% 转码/滤镜能力的 GUI 化，整个项目最稳定的部分 |
| 水印叠加 | 主线 | 项目立项的原因，在这上面花的时间比转码本体还多 |
| 画中画 /封装 / 流提取 | 支线 | 与水印共享同一套滤镜链和位置编辑器 |
| 可视化编辑器（裁剪/位置/轨迹/画布） | 支线 | 为水印、画中画、裁剪服务的图形化手段 |

拿这些支线能力去实现别的效果（局部马赛克、动感叠加、轻量非线性编辑之类）完全没问题——它们是能跑的、也在正常维护，只是**不是设计目标**，属于边际收益：用得上是赚到，用不上也不影响主线。

## 为什么做这个工具

做它之前，我的流程是：批量转换和裁剪用 bat 脚本，复杂的去 Shotcut。

转折点是「左右平铺」这类活：在 Shotcut 里要先改项目分辨率，左边视频的位置归 0，右边视频的 x 改成左边的宽度——每一步都手动，两条视频还好，多了要命。于是我做了这个工具：两个视频拖进去，高度（或宽度）对齐一下，平铺，输出。

现在我已经很久没打开 Shotcut 了。

## 更新节奏建议

- **只做批量转换的话，没必要追新。** 更新日志里的大多数条目是支线功能的打磨和联动修复，转码主线一直很稳。偶尔（比如一两个月）来看一眼有没有你用得上的修复就够了，没必要每次更新都跟着换文件。
- **编译版本来就是滞后的。** 源码带自动编译脚本，fork 按需编译即可；装了 Python 的推荐直接跑脚本。
- 作者自己就是**脚本形态**使用（.pyw 直接跑，只依赖一个 dnd2 拖拽库，刻意不引入其他任何第三方库），不打包部署——所以编译文件的更新频率不代表项目活跃度。

## 出问题怎么办

主线转码几乎没大改，真出问题多半是边界情况（冷门的容器/编码组合）。支线功能按「能组合、不互斥」的原则迭代，每次改动的验证以主转码不回归为底线。提 issue 时把 FFmpeg 的完整命令行和报错输出贴上，修起来最快。
