# FFmpeg 配置指南（setupFFmpeg）

本工具本身**不包含** FFmpeg 可执行文件，它需要你在系统中准备好以下三个程序后才能正常工作。

| 程序 | 文件名 | 是否必需 | 用途 |
| --- | --- | --- | --- |
| FFmpeg 主程序 | `ffmpeg`（Windows 为 `ffmpeg.exe`） | **必需** | 转码、合并、滤镜等核心功能 |
| FFprobe 探测工具 | `ffprobe`（Windows 为 `ffprobe.exe`） | **必需** | 读取视频/音频信息（时长、分辨率、编码、流轨等） |
| FFplay 播放器 | `ffplay`（Windows 为 `ffplay.exe`） | 可选 | 实时预览、播放测试（不装也能正常转码） |

> 建议把三个文件放在**同一个目录**下，方便统一管理。缺少 `ffprobe` 时部分需要分析媒体信息的功
> 能会受限；缺少 `ffplay` 时仅预览/播放相关功能不可用，转码不受影响。

---

## 一、下载 FFmpeg

本程序只是一个外壳 GUI，本身不包含任何编解码器，必须依赖外部的 **FFmpeg 本体** 才能工作。

- **下载地址**：https://github.com/BtbN/FFmpeg-Builds/releases
- **推荐版本**：`ffmpeg-*-win64-gpl-shared`（64 位系统）／`ffmpeg-*-win32-gpl-shared`（32 位系统）

### 为什么推荐「shared（共享）版」

程序用到 FFmpeg 三件套：`ffmpeg`、`ffprobe`、`ffplay`。这三个 exe 都依赖同一套底层库
（`avcodec`、`avformat`、`avutil` 等）。**shared 版**把这些公共库单独抽成 `*.dll` 放在同级目录，
三个 exe 共享同一份，解压后的总体体积较小。

如果改下载各自独立、库文件内嵌的版本，三件套各自的 exe 会把同一套库重复打包一遍，
加起来体积大约会 **大 2 倍**。普通使用场景 shared 版完全够用，是体积与功能的最佳平衡。

### 下载与解压

1. 在发布页找到最新的 `ffmpeg-*-win64-gpl-shared.zip`，下载；
2. 解压后目录里的 `bin\` 子文件夹即包含 `ffmpeg.exe`、`ffprobe.exe`、`ffplay.exe`
   （以及它们共享的一批 `.dll`）；
3. 把整个 `bin\` 或里面的文件，按下方「二、三种集中解压位置」放置即可。

> 备选镜像：https://www.gyan.dev/ffmpeg/builds/（选 `ffmpeg-release-essentials.zip`）。
> 两者二选一即可，无需重复下载。

## 二、FFmpeg 的三种「集中解压位置」

软件的自动查找逻辑会按固定顺序扫描以下位置，**任意一个**把文件放对就能被识别，无需任何额外配置。
三种位置都有效，但针对前面推荐的 **shared（共享）版**（解压后有一大堆 `*.dll` 库文件），整理方式有别：

- **🌟 最推荐：配置为系统环境变量目录（PATH）**——一次配置，全系统程序（包括本程序、以及你机器上其他需要 FFmpeg 的软件）都能直接用；对已经配好 PATH 的高手而言，下载后什么都不用动就能直接跑本程序。
- **推荐的实际结构：放进 `_internal` 子目录，或直接把 `bin` 解压到 exe 同目录**——把零散的 DLL 收进子文件夹，主程序目录保持干净。
- **也能用：直接放 exe 同目录**——对 shared 版来说会把几十个 DLL 散在主程序旁边，略显杂乱，但功能无任何影响。

### 位置 1：exe 同目录（最省事，但 shared 版会散落大量 DLL）

把 `ffmpeg.exe`、`ffprobe.exe`、`ffplay.exe` **直接解压到软件主程序所在目录**。

```
你的软件目录\
├── FFmpeg简易转换合并.exe              ← 主程序
├── 水印轨迹编排器 多轨道.exe           ← 外挂程序（同包附带）
├── ffmpeg.exe                          ← 放在这里即可被自动找到
├── ffprobe.exe
├── ffplay.exe
└── 其他 `*.dll` 库文件
```

- 优点：零配置，复制走整套目录也能用。
- 注意（shared 版）：这里会同时出现几十个 `*.dll` 库文件，主程序目录显得杂乱；想要整洁请改用
  位置 2 的 `_internal` / `bin` 子目录。


### 位置 2：子目录 `_internal` 里，或直接把 `bin` 解压到 exe 同目录（推荐结构，尤其适合 shared 版）

有两种摆放都可行：

**方式 A — 放进 `_internal` 子目录**（PyInstaller 文件夹版的标准位置）

```
你的软件目录\
├── FFmpeg简易转换合并.exe              ← 主程序
├── 水印轨迹编排器 多轨道.exe           ← 外挂程序
├── _internal\                          ← 把 ffmpeg 放这里
│   ├── ffmpeg.exe
│   ├── ffprobe.exe
│   └── ffplay.exe
│   └── 其他 `*.dll` 库文件
└── ...
```

**方式 B — 解压出 `bin` 子目录**（保留官方压缩包结构，最整洁）

```
你的软件目录\
├── FFmpeg简易转换合并.exe
├── 水印轨迹编排器 多轨道.exe
├── bin\                                ← ffmpeg 官方 zip 解压后的 bin
│   ├── ffmpeg.exe
│   ├── ffprobe.exe
│   └── ffplay.exe
│   └── 其他 `*.dll` 库文件
└── ...
```

- 软件会扫描主程序目录下**所有一级子目录**，子目录里的 `ffmpeg.exe` 同样能被找到。
- 如果你把官方 zip 整个解压到同目录，通常就自动形成 `bin\` 结构，什么都不用改。

### 位置 3：配置成系统环境变量目录（PATH，🌟 最推荐，一次配置全系统通用）

把三个 exe 和其他 `*.dll` 库文件放到任意一个**已在系统 `PATH` 中的目录**，或把它们的目录**加入 `PATH`**。

**步骤（Windows 10/11）：**

1. 把 `ffmpeg.exe`、`ffprobe.exe`、`ffplay.exe` 和其他 `*.dll` 库文件放到一个固定目录，例如
   `C:\Tools\ffmpeg\`（不要带中文或空格更稳妥）。
2. 按 `Win + S` 搜索 **「编辑系统环境变量」** 并打开。
3. 点击右下角 **「环境变量」**。
4. 在「系统变量」或「用户变量」中找到 **`Path`**，双击编辑。
5. 点击 **「新建」**，粘贴 `C:\Tools\ffmpeg\`，确定保存。
6. **重启**所有已打开的命令行窗口与软件，使 `PATH` 生效。

**验证（命令提示符或 PowerShell）：**

```bat
ffmpeg -version
ffprobe -version
```

能打印出版本号即表示 PATH 配置成功。

- 优点：全系统任意程序都能直接调用，`ffmpeg` 升级只需替换一处；对已经配好 PATH 的环境
  （多数开发者/高手机器），下载本程序后**无需任何额外操作**即可直接运行。
- 缺点：配置路径较深，初次设置容易漏掉「重启软件」这一步。

## 三、软件内部的查找顺序（了解即可）

程序启动时按以下优先级定位 FFmpeg，遇到第一个有效文件即采用：

1. **主程序同目录**下的 `ffmpeg.exe` / `ffmpeg`；
2. 主程序目录的**一级子目录**（如 `bin\`、`_internal\`）中的对应文件；
3. 打包为单文件时，请用1 4
4. **系统 `PATH`**（`shutil.which` 回退）。

因此上面「三种位置」本质上都落在这一套查找链里，放哪都行，互不影响。

---

## 四、第四种方式：软件内手动指定目录（优先级最高）

如果你不想动 PATH、也不想把文件塞进软件目录，可以在软件里**手动指定 FFmpeg 目录**：

1. 打开软件主界面上方的 **「信息与播放器」**；
2. 勾选 **「启用自定义 FFmpeg 目录」**；
3. 浏览并选择 **只含三个 exe 的那个文件夹**（例如 `C:\Tools\ffmpeg\` 或解压出的 `bin\`）；
4. 软件会优先使用该目录里的 `ffmpeg.exe`、`ffprobe.exe`、`ffplay.exe`。

> 手动指定目录的优先级高于上面的自动查找。该设置会记忆，下次启动自动生效。

## 五、验证软件已正确识别

启动软件后：

- 主界面状态栏 / 信息区应显示已找到的 `ffmpeg` 与 `ffprobe` 路径；
- 拖入一个视频文件，能正常解析出时长、分辨率、编码等信息，说明 `ffprobe` 工作正常；
- 执行一次简单转码能成功输出，说明 `ffmpeg` 工作正常；
- 若提示「未找到 ffmpeg / ffprobe」，请回头检查上面任一种位置是否放对、路径是否含中文或空格、
  以及（PATH 方式）是否已重启软件。

## 六、常见问题（FAQ）

**Q1：只放 `ffmpeg.exe` 行不行？**
可以转码，但建议连同 `ffprobe.exe` 一起放，否则需要分析媒体信息的界面功能会受限或报错。

**Q2：路径里能用中文/空格吗？**
能，但遇到莫名其妙的问题时，先把 FFmpeg 目录换到纯英文、无空格的路径（如 `C:\Tools\ffmpeg\`）
排查，成功率最高。

**Q3：多个 FFmpeg 版本会冲突吗？**
软件只取查找链里**第一个**命中的文件，不会同时加载多个。若发现版本不对，检查 `PATH` 里是否有
更早的旧版本，或删掉软件同目录下的旧 exe。

**Q4：绿色版 / U 盘携带怎么放最稳？**
用「位置 1：exe 同目录」或「位置 2 方式 B：bin 子目录」，整套目录拷走即走，不依赖系统 PATH。

**Q5：打包成单个 exe 后找不到 FFmpeg 怎么办？**
单文件 exe 运行时解压到临时目录，软件同目录方式失效。请用「位置 1 的 」主程序同目录
或直接「位置 3 的 PATH」，或在软件内手动指定目录。
